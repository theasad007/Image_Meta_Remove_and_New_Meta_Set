**Verification status (Phase 3 COMPLETE):** inspect proven for all 5 formats (Phase 2). Cleaning proven with remove→re-inspect→payload-equality gates for JPEG/PNG/WebP/AVIF plus HEIC still layouts incl. one real-encoder layout (scoped Proven; other layouts stay Unsupported/Partial). Policy: `privacy_safe_default` removes proven-safe EXIF(non-technical)/XMP/IPTC/COM/text-chunks; preserves pixels, orientation(-minimal EXIF), ICC/`colr`, palettes/alpha, structure; retains unassessed APPn/chunks/uuid as `retained_unsupported` (coverage-limited partial, never silent). `aggressive_when_proven_safe` additionally drops unidentified APPn/ancillary chunks; ISOBMFF identical under both (item-graph safety dominates). Statuses: `verified_clean` / `partially_cleaned` / `unchanged_no_target_tags` downloadable; `failed`/`not_verified`/`unsupported` never downloadable. 30+1 fixtures, ExifTool before/after baselines, Pillow + heif-convert pixel-equality evidence, 82 unit + 19 E2E green in real Chrome vs production `out/`.

**Machine-readable result statuses (contract for Phase 5 ZIP/CSV/PDF):** `verified_clean` → `verified_supported_scope` (only supported inspected groups confirmed, incl. `C2PA` absence-after when a store was removed); `partially_cleaned` → `partial` (retained `retained_unsupported` items enumerated); `failed` → `failed` (errors enumerated, no output); `unsupported` → `unsupported` (reason enumerated); `not_verified` → `not_verified` (withheld); category-level `not_inspected` (C2PA/video paths) → `not_inspected`. UI badges, `changes[]`, and future reports all derive from these — no second counting source.

**ISOBMFF design constraints (AVIF/HEIC, browser-only, format-preserving):** parse `size/type/largesize` + FullBox version/flags; follow `iloc` extents (method 0 absolute, 1 `idat`-relative); never delta-patch offsets — rebuild `meta` (regen `iinf`/`iloc`/`iref`) + fresh `mdat` and recompute all sizes/offsets; copy compressed image bytes verbatim (decode-compare in tests); preserve `pitm`/`iprp`, alpha, `colr`/HDR, thumbnails/aux/grid/overlay refs; refuse sequences (`msf1`/`heis`, `moov`-based) as `Unsupported`. Security: cap `itemCount×extentCount` allocation (cf. CVE-2026-85715), validate box lengths (cf. CVE-2026-53496), catch parse errors per-file in Workers.

**Worker decision (Phase 4, evaluated honestly):** no Web Worker ships. ExifReader's XMP path needs `DOMParser`, absent in workers — solvable via `@xmldom/xmldom`, but the full inspect→clean→verify chain has no proven static-export worker bundling, and the chunked main-thread scheduler (concurrency 1, ranged reads, per-file buffer release, UI yields between 256 KiB ZIP slices) measured responsive (50-file E2E shows no freeze; 1000-file completes with heap 21→121 MB). A main-thread `setTimeout` loop is NOT called a Worker anywhere. Revisit with a worker-safe XML parser + bundling proof if profiling demands it.

**ZIP technology (Phase 4):** `fflate@0.8.3` (MIT, zero dependencies), lazy-loaded on first archive action only (verified outside the initial page chunk). STORE via `ZipPassThrough` (no recompression; CRCs computed by the writer); streaming `Zip` with ordered, chained File-System-Access writes where available (explicit save gesture), Blob assembly fallback otherwise (500 MB estimate warning, never a cap); no Zip64 — estimated archives past 4 GiB are refused with guidance instead of corrupted. Chrome 155 + Firefox 157 E2E-proven; Safari/Firefox Blob fallback path is the default expectation there.

**Reporting contract (Phase 5, extended Phase 6):** one frozen `ReportSnapshot` per export (queue order + inspections + cleanings + rewrites + ZIP manifest at boundary + options + scopeId) feeding CSV + PDF + embedded copies identically. `pdf-lib@1.17.1` (MIT + MIT-licensed deps, lazy-loaded only on PDF actions; standard Helvetica, no bundled/remote fonts — non-WinAnsi glyphs shown as counted `?` with methodology disclosure, exact values stay in UTF-8 CSV; deterministic snapshot-timestamped dates; no user data in document properties). CSV: exact 36-column schema + tags ledger, RFC-4180 + BOM, formula guard (numeric GPS stays numeric; profile company/author/keywords guarded), summary redaction default with explicit opt-in, chunked async generation with progress + cancel. Rewrite records use `requestedOperation=rewrite` + mode in the Cleaning Mode column; Verified Rewritten counts derive only from re-observed `rewritten/verified` changes. ZIP `reports/` entries come from the same snapshot bytes as standalone downloads (tested byte-equal). Rewritten outputs archive as `images/<stem>-rewritten.<true-ext>` and take precedence in the manifest when present (cleaned outputs stay separately downloadable).

## Phase 6A architecture (auth entry + admin foundation)

- **Hero CTA:** the “See how it works” link is replaced by a `HeroAuthCta` client control in the same location/styling/visibility: signed-out → “Sign in / Sign up with Google” (existing popup flow, queue untouched); signed-in → “Account / Metadata Profile” anchor (`#account`) plus an “Admin Dashboard” link for verified superadmins only; unconfigured builds show an honest disabled note. The `#how-it-works` card keeps its anchor. Header/navigation otherwise unchanged.
- **Authorization:** Auth custom claim `superadmin: true` (no email allowlists, no client role flags). UI gates (hero/admin links, `/admin` client guard, self-suspend refusal) are convenience only — `firestore.rules` re-checks the claim on every privileged path, including `list` on `users/{uid}` and all of `adminSettings/*`.
- **Directory:** `users/{uid}` minimal records auto-created on sign-in (best-effort, never blocking guests/queue); suspended status denies the owner's profile read/write via a rules `get()` check while leaving Auth login and anonymous cleaning intact. No `listUsers` in the browser, ever.
- **Admin page (`app/admin/page.tsx`):** static-export safe (prerendered shell, client guard), paginated directory list (50/page) with search/status filter, counts, confirm-gated suspend/restore with self-guard, usage-policy recorder with NOT-enforced badges, loading/empty/error states, backfill guidance.
- **Bootstrap:** `scripts/bootstrap-superadmin.mjs` (local-only, dynamic `firebase-admin` import, explicit UID + `--confirm` gate, verify-after-write, revoke mode). Service-account keys live outside the repo (gitignored); nothing admin enters `NEXT_PUBLIC_*`, bundles, `out/`, or version control.
- **Limits honesty:** usage-policy values are stored but read by nothing — no caps activate, no per-file Firebase writes, no activity logging. Real metering needs a separate architecture decision.

## C2PA removal design (milestone 14 Oct 2026)

- **Locator before writer:** `src/lib/metadata/clean/c2pa-locate.ts` holds
  all structural identification (JPEG EN/Z/marker grouping mirroring the
  official delete path plus mandatory LBOX+TBOX duplication; PNG/WebP JUMBF
  header + fixed-UUID proof; BMFF box-UUID + purpose + inner-UUID proof).
  Writers only delete positively identified carriers — never by name alone.
- **Scope gate:** `resolvesC2paRemovalTarget` (explicit `descriptive`, or
  `ai_markers` with C2PA in the file's AI evidence). Out-of-scope stores are
  retained with a scope reason; unproven same-name carriers are always
  retained, even aggressive.
- **Safe-fail policy:** `C2PA` joined the verify target groups, so a removed
  claim verifies only on `not_detected` after real re-inspection;
  `detected`/`not_inspected` after cleaning fails closed with output
  withheld. ISOBMFF drops recompute all `iloc` offsets via the existing
  full-rebuild path (no delta patching).

## Phase 6 architecture (Firebase + rewrite, 15 Oct 2026)

- **Firebase static-client:** `firebase@13.0.0` (modular, MIT-adjacent Apache-2.0 via Google) + `@firebase/rules-unit-testing@6.0.0` (dev-only). Only `firebase/app`, `firebase/auth`, `firebase/firestore` are imported, always via lazy `import()` so guests never download them (guest bundle grep-verified free of firebase/zip/pdf/media libs). No Admin SDK, no Functions, no Storage, no API routes. Config via `NEXT_PUBLIC_FIREBASE_*` (build-time inlined; `.env.local` gitignored, `.env.local.example` committed with placeholders + Spark quota notes). `firestore.rules` enforces owner-only `users/{uid}/profile/main` with field/type/size ceilings mirroring `fields.ts` (title 200, description 2000, keywords string ≤2000/≤30 tags, schemaVersion 1–10; `isAdmin`/`plan`/nested/unknown paths denied). `firebase.json` pins the rules file + emulator ports (dev-only).
- **Rewrite engines:** zero-dependency TS writers reusing cleaner parsers/validators: `codecs.ts` (TIFF IFD0 merge preserving unknown tags/sub-IFDs/thumbnails, XMP DOM merge preserving unknown elements, IPTC APP13 merge preserving foreign IRBs), `jpeg.ts` (APP1 EXIF/XMP + APP13 IPTC, segment-size guards, extended-XMP refusal), `png.ts` (eXIf + iTXt XMP, CRC recompute, order preserved), `webp.ts` (EXIF/XMP + VP8X bit-set/synthesis from canvas size, animation never routed), `isobmff.ts` (Exif + XMP mime items created/merged, `iinf`/`iloc`/`iref` rebuild with cdsc for new Exif, offsets recomputed). Orchestrator `rewrite.ts` enforces budget/sniff/kind gates, replace-vs-update semantics, C2PA honesty (replace reuses cleaner scope; update preserves + re-validates with invalidation warning; never forges), payload equality, output re-inspection, and per-field re-observation. Queue pipeline `rewrite-pipeline.ts` mirrors the cleaning pipeline (sniff→inspect→rewrite, total function, 64 MB budget, no count cap).
- **UI:** `AuthPanel` (config-unavailable honesty, popup-blocked/closed/unauthorized-domain/offline/rate-limit mapping, cancel preserves queue, sign-out clears in-memory profile only), `ProfilePanel` (10 validated fields with visible limits, Bengali/Unicode UTF-8, mapping preview, Save/Load/Delete with acknowledged-write semantics; canonical apply source = current form values), `RewritePanel` (replace/update radios with privacy explanations, field checkboxes, per-format + C2PA + Phase 7 caveats, bulk apply with cancel), `RewriteResultPanel` (requested→observed→verification per field, `-rewritten` download only for verified/partial). Queue rows gain gated Rewrite actions; cleaned outputs are never destroyed by rewrite attempts.
