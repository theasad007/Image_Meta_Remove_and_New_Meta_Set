# 07 — Known Technical Limitations (honest constraints, Spec v1.1)

1. **No 100% AI-invisibility:** stripping EXIF/XMP/C2PA doesn't erase watermarks, external registries, platform labels, or image-content signals. Never claim otherwise.
2. **C2PA:** embedded Manifest Stores are detected and validated locally in the browser with official `@contentauth/c2pa-web`/c2pa-rs WASM. The row reports the validation state, claim generator/software agents and AI-associated digital source types (including OpenAI when actually named). A parser failure remains `not_inspected`; a completed no-manifest preflight is `not_detected`. **P0 proof (14 Oct 2026):** own c2patool-signed fixtures (`signed-c2pa.jpg` APP11, `signed-c2pa.png` real `caBX`) exercise `detected` in Chromium/Firefox — 8 tags, `Valid` + 1 untrusted-credential failure, presence never equated with trust; tampered/cleaned outputs re-inspect `Invalid` with counted failures while retaining manifest bytes. **C2PA-removal milestone (14 Oct 2026):** structurally identified stores are now removed and proven absent (see `02` §2.7); unproven JUMBF/`uuid` and out-of-scope stores stay retained + partial. Removal never implies erased watermarks, external registries, or platform labels. Details + SHAs: `docs/09-c2pa-openai-proof-report.md`, fixture README.
3. **JPEG:** `Privacy Clean` retains ICC + (for rotated shots) orientation-only EXIF (~32B) by default to avoid color/shift breakage — labeled `Retained intentionally`; `Aggressive Strip` optional with warnings.
4. **PNG/WebP rewrite proven (Phase 6); GPS still Phase 7:** `eXIf`/XMP chunks are valid rewrite homes (proven); IPTC has no PNG/WebP home and is disclosed unsupported. No silent JPEG conversion.
5. **AVIF rewrite proven; HEIC rewrite proven for tested still layouts:** ISOBMFF item insert/merge preserves `pitm`/`iprp`, alpha, `colr`/HDR, thumbnails/aux/grid/overlay refs and all image-item offsets; stripping container properties that merely resemble metadata corrupts the file. Sequences (`msf1`/`heis`), grids/overlays/aux-refs, idat-backed items, 64-bit iloc fields, v0/v1 untyped entries, multi-mdat and movie boxes all refuse explicitly. Real-encoder discovery: libavif writes `iprp` WITHOUT FullBox version/flags — tolerated with layout-preserving rebuild. ExifReader CVEs clear in installed 4.50.0; per-file isolation + allocation caps retained as policy. `aeo-image` (MIT) not adopted — custom engine proven instead. No silent AVIF/HEIC→JPEG fallback, ever. ExifReader is read-only: it can never perform removal/rewrite/GPS-write. Remaining wish-list (not blockers): iPhone-original (Apple-encoder) HEIC as an extra layout data point; broader untested layouts stay Unsupported/Partial with no global HEIC claim.
6. **ExifReader input/output safety:** never pass untrusted strings to `load()` (SSRF — pass `File`/`ArrayBuffer`); escape every tag value before DOM insert (XSS via crafted XMP/Exif); clamp `metadataRange.end` before slicing; cap `maxDecompressedSize`; never use `accept="image/*"` on file inputs (strips GPS on Android — list extensions explicitly). Invalid XMP packets are tolerated per-group (observed once with a malformed PNG iTXt: xmldom logs, group absent, parse continues).
7. **Framework patch window:** 16.4.0 pinned; Oct 14 out-of-band security update (2 Critical + 1 High) still unreleased — re-verify before any production deploy. 15.x EOL ~21 Oct 2026; 14.2.33 must not ship. Dev-only eslint-config-next/micromatch high-severity chain (full `npm audit` only; `--omit=dev` clean) has no non-breaking fix; not shipped to browsers. **Phase 6 Gate B (resolved 15 Oct 2026):** the 4 production highs via `@grpc/grpc-js@1.9.16` (GHSA-m9gg-hp2v-232j + GHSA-f596-whhp-79r4 through `@firebase/firestore@4.18.0`) were fixed with a minimal `overrides` pin to `@grpc/grpc-js@1.13.7` — browser exposure was nil (Firestore web uses WebChannel; only setting-name strings in `out/`), firebase/firestore versions unchanged, and typecheck/lint/unit/rules-emulator/build/E2E all re-ran green with `npm audit --omit=dev` at 0.
8. **Preview gap:** AVIF uses native browser decoding; HEIC uses native decoding where available and lazy `heic-to`/libheif WASM elsewhere. If both fail, the row shows a compact image icon. File-level inspection and cleaning never depend on preview decoding.
9. **Codec/patent stance:** metadata path is parse-only and codec-free (no HEVC decoder bundled for ops). Optional HEIC display decoder (LGPL-3.0 libheif builds) stays lazy, display-only, and replaceable; use legally distributable free/open-source deps only, no paid codecs/APIs.
10. **Inspection/cleaning budgets (Phases 2–3):** 64 KiB sniff window + ranged reader fetches; 64 MB/file inspect+clean budget (explicit failed outcome above it, never silent — E2E-proven with a 65 MB file); concurrency 2 inspections with cancel tokens; tag/value caps (400 tags/category, 500 chars/value); Web Worker deferred to Phase 4 with documented rationale. File ranged reads, 50-file queue, cancel/stale guards, repeated downloads and request-log locality all E2E-proven in real Chrome vs production `out/`. Cleaning holds input + output buffers transiently per file (bounded by the budget); no batch accumulation (Phase 4 scope).
11. **Video:** MP4 box coverage is container-dependent; MOV/WebM later; video inspection visibly `not_inspected` in Phase 2 (no MediaInfo.js yet); no “all video metadata” promise. Practical browser cap ~100–200MB/file; WASM hard cap 2GB (1GB some forks); mobile often lower. OOM → clear error, no file.
12. **Scale:** “No artificial cap” means no business limit — proven to 1000 files in-browser (50 s, heap 21→121 MB on desktop Chrome; tiny fixtures — larger real files will be slower and hungrier). RAM/storage/CPU still bound real batches. Bounded concurrency (1) + chunked scheduling + per-file buffer release + ZIP re-read-one-Blob-at-a-time; 1000-row DOM without virtualization measured OK (sub-second interactions); huge archives may need File System Access streaming (implemented where available) with Blob fallback + 500 MB estimate warning. AVIF/HEIC `iloc`-near-EOF layouts mean `metadataRange.end` often ≈ file size — budget full-file reads.
13. **ffmpeg.wasm:** evaluation only — slow single-thread, codec subset, LGPL/GPL core licensing review, COOP/COEP unavailable on static hosting.
14. **Firebase Spark:** 50k reads/20k writes per day, 1GiB, 10GiB/mo egress; over-quota = shutoff till cycle or Blaze upgrade. Profile-only (`users/{uid}/profile/main`), minimal I/O (read once per sign-in, write only on Save). Rules must be published separately; committed rules alone secure nothing.
15. **OSM tiles:** best-effort, no SLA; attribution + caching + no-scrape mandatory; map must degrade to manual input. No map in Phase 2 (correctly — Phase 7 scope).
16. **Verification rule:** never claim removed/rewritten unless re-read confirms (`Verified removed/updated`, else `Partial/Failed/Unsupported`). AVIF/HEIC additionally require third-party decode (ImageMagick/exiftool/Apple stack) before any ready label.
17. **Privacy:** reports default to Summary (redact GPS/creator/serials/prompts — proven on real digits across CSV + PDF + properties); explicit opt-in exposes locally only; CSV formula-cells escaped (numeric GPS stays numeric); filenames sanitized; parsers hardened (chunk-length bombs, bad UTF, decompression limits, ISOBMFF box/`iloc` budgets). No media/metadata/reports leave the browser — verified by zero fetch/XHR/Beacon code paths, static-only `out/`, E2E request-log proof over report downloads, and no storage APIs in `src` (no localStorage/IndexedDB writes).
18. **ZIP scope (Phase 4):** fflate STORE archives under `images/` with deterministic traversal-proof names; no Zip64 — estimated archives past 4 GiB are refused with guidance; File System Access streaming where available (explicit save gesture), Blob fallback otherwise (Safari/Firefox default path); headless pickers can't complete native save dialogs (E2E forces Blob path; FS sink covered by ordered-write unit tests). No `videos/` folder is fabricated — Phase 8 owns that.
19. **Reports scope (Phase 5, extended Phase 6):** PDF uses standard fonts only — non-WinAnsi glyphs render as counted `?` with methodology disclosure (exact values stay in UTF-8 CSV; Bengali/Unicode rewrite values verified in CSV + ExifTool); tag appendix capped at 400 transitions (ledger complete); **geotag columns remain n/a until Phase 7; rewrite counts are live from Phase 6**; per-file timestamps blank/`not_recorded` (never invented); 1000-file PDF measured at 125 ms node; FS-picker streaming unautomatable headless (mock-tested).
19. **No Worker in Phase 4 (documented, not hidden):** chunked main-thread scheduling measured responsive; worker-safe XML parsing + static worker-bundling proof deferred. Output Blobs are retained per processed file by design (needed for ZIP/single download) with a 500 MB estimate warning — not a cap, and the only unbounded structure; clear the queue to release.
20. **Phase 6A auth/admin notes:** live Google OAuth + claim promotion are **unverified** without a real Firebase project + authorized Hostinger domain (runbook + checklist in `docs/10-admin-setup.md`). Firestore rules tests pass on the real emulator (15/15 with Java 21+; command: `npm run test:rules` with `JAVA_HOME` pointing at a Temurin 21+ JDK). `npm run test:rules` fails loudly if the emulator cannot start (never green-with-skip); plain `npm test` skips emulator suites explicitly and reports skips separately. Sign-in popups can be blocked/closed, providers can be disabled, and redirect fallback is not assumed on static hosting — all mapped to truthful errors with queue preservation. Suspension gates saved-profile/admin reads only; Google login and anonymous cleaning are unaffected by design. Usage-policy values are never enforced (no caps, no per-file metering, no activity logging) — real limits need a separate architecture decision. The browser never calls `listUsers`; the admin list is the Firestore directory and is labeled as such. Rewriting never forges C2PA manifests; retained C2PA after update-mode edits may be invalid (re-validated state shown, never claimed valid).
