# 06 — Deployment: Hostinger Static (+ Firebase setup for Phase 6)

- Build: `next.config.ts` → `{ output:'export' }` → `next build` → `out/`. Upload `out/` contents to Hostinger `public_html` (Cloud/static). No Node server, no SSR routes.
- Forbidden with export: server actions, API routes for processing, runtime cookies/middleware requiring Node, `next/image` default optimizer (use custom loader or `images.unoptimized`), `getServerSideProps`/ISR.
- WASM assets (`mediainfo`, `c2pa`, optional `ffmpeg-core`, optional HEIC display-decoder) served as static files with correct MIME (`application/wasm`); verify Hostinger serves them, else self-host path rewrite. Verify `image/avif`, `image/heic`, `image/heif` MIME/download behavior for direct outputs; app must not rely on inline HEIC rendering outside Safari.
- Client-only modules (Workers, WASM, Leaflet, Firebase, pdf-lib, mediainfo.js, ffmpeg trial, ISOBMFF engine, ExifReader ≥4.41.1) must be `dynamic(...,{ssr:false})` / lazy `import()` so prerender doesn't execute browser APIs. Firebase Auth/Firestore load only on sign-in/profile actions — guests never fetch them.
- COOP/COEP (`SharedArrayBuffer` for multithread ffmpeg) generally **not settable** on cheap static hosts → plan assumes single-thread fallback; never require MT build.
- Fonts/tiles: OSM tiles are remote (attribution required); everything else local. Add cache headers where Hostinger allows; test Firefox/Safari + mobile.
- Env: Firebase web config is public; never ship Admin keys. Copy `.env.local.example` → `.env.local`, fill the four `NEXT_PUBLIC_FIREBASE_*` values (Firebase console → Project settings → Web app), then rebuild (`NEXT_PUBLIC_*` inlines at build time) and redeploy `out/`. Without them the app runs fully as a guest. Donate URL via env (`NEXT_PUBLIC_DONATE_URL`).
- Firebase console prerequisites (do once per project): enable Authentication → Google provider; add the Hostinger domain (and `localhost` for testing) under Authentication → Authorized domains; create Firestore (Spark) and **publish `firestore.rules`** (Firebase console → Firestore → Rules, or `firebase deploy --only firestore:rules`) — committing the file does not secure the database. Spark quotas: ~50k reads / ~20k writes per day, 1 GiB stored, ~10 GiB/mo egress; this app reads once per sign-in and writes only on Save.
- Manual live-login checklist (required before claiming OAuth proven): sign in on the Hostinger URL (popup allowed), save a profile, reload and reload profile, sign out and confirm guest flows + queue intact, apply to one JPEG + one PNG and ExifTool-verify downloads, confirm Firebase console shows only `users/{uid}/profile/main` with profile fields.
- `npm run test:rules` needs a free Temurin/Oracle/Zulu JDK 21+ for the Firestore emulator. This environment already has Temurin 25 preinstalled: run `export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-25.jdk/Contents/Home` (plus `$JAVA_HOME/bin` on `PATH`) for the test invocation only — no system Java change, no paid download. Tested rules file == published file (same `firestore.rules` path in `firebase.json` and in `rules.test.ts`).
- Owner admin bootstrap (one-time, after first owner sign-in): `node scripts/bootstrap-superadmin.mjs --project <id> --uid <verified-uid> --confirm <verified-uid>` with `GOOGLE_APPLICATION_CREDENTIALS` pointing at a service-account key kept **outside** the repo (gitignored). Then sign out/in (or Refresh login status) and open `/admin`. Full runbook: `docs/10-admin-setup.md`.
- Smoke: clean `next build`, load `/`, upload→inspect→clean→rewrite (signed-in)→ZIP→CSV/PDF offline-after-load check (DevTools Network proves no media upload; signed-in traffic is Firebase auth/profile only).
